# Red Bull TV

官方入口：[Red Bull TV](https://www.redbull.tv/en_US)、[Live TV](https://www.redbull.tv/en_US/epg)。从独立实验台迁入主项目；不依赖实验台进程、社区 IPTV 列表或第三方转播源。

## 使用

在「源管理 → 内置抓取模块 → 海外 → Red Bull TV」启用，刷新主项目 M3U 订阅即可。默认关闭。轮播和赛事分别位于「红牛轮播」「红牛赛事」，可直接使用主项目网页播放器。已删除原精选列表的一路 Red Bull TV；旧内置订阅缓存中的同名条目也会过滤，自建订阅不受影响。

当前轮播为综合、板式网球、自行车、户外探险、赛车、冲浪、滑板、冬季运动、极限精选，共 9 路。轮播目录每小时从官方集合重新发现；公开在播赛事随主项目源刷新检查同步，默认检查周期 5 分钟，模块最短刷新间隔 1 分钟。未来预告、回放和受限内容不写入直播列表。主项目会保留上次成功目录以应对目录临时失败，播放仍须通过当前官方状态核验。

「设置 → 网络代理」控制全部取址与媒体流量，放行域名为 `redbull.tv`、`redbull.com`、`akamaized.net`、`liiift.io`。留空时沿用环境／系统代理，都没有时按服务器路由直连；播放设备始终访问服务器。切换代理地址会作废匿名会话及解析缓存，不强制国家代码，也不绕过登录、DRM 或地区限制。

## 实现

- `api.js`：从官网分段 Next RSC 读取匿名地区参数和目录 ID，只保留必要非票据字段。官方频道集合与 Live Now 动态发现；活动卡展开其 `live_programs` 场次，支持多场地。订阅使用官方 UUID 派生的稳定引用，重启后直接按 ID 解析。
- `index.js`：注册海外模块、默认开关、代理目标和域名，提供主项目 `fetch`、`resolve`、`fetchProxyMedia`。轮播台标经内置台标库的引用映射提供，赛事直播间留空。
- `hls.js`：红牛赛事的追加式 EVENT 清单裁成最近三分钟的滑动窗口，正确延续媒体序号、discontinuity 和初始化段；避免数小时历史清单挤满主项目的共享代理表。
- 播放时复核动态状态与公开权限，15 秒内合并重复解析。保留所有官方画质、音轨和字幕，最高视频档在前。结束、回放及已带 ENDLIST 的赛事不会被作为直播重新打开。
- 官网/API、媒体和重定向逐跳限制在已确认域名；清单中的媒体 URI 同样校验。加密清单明确拒绝。关闭模块后，已收藏入口和已发出的媒体引用也停止服务。
- 尚未接入官方逐节目 XMLTV，不以赛事预告冒充轮播节目表。

## 验证

离线回归：`node scripts/test-redbull.mjs`。包含预告→在播→结束/回放、多球场、缓存过期、权限、异常分页、域名、音轨/字幕/初始化段、追加清单、共享代理容量、模块开关和旧频道清理；已纳入 `npm test`。

真实端到端检查直接读取运行中主项目的 `/m3u`，不用实验台：

```sh
node scripts/probe-redbull.mjs --base=http://127.0.0.1:1958 --seconds=15 --report=/tmp/redbull-short.json
node scripts/probe-redbull.mjs --base=http://127.0.0.1:1958 --seconds=720 --only=c81f8686,ee30c528,f0ee7f41 --report=/tmp/redbull-long.json
```

`--only` 按稳定引用或频道名称筛选，示例中的赛事 ID 仅是本次验收场次，日后按当前订阅替换。短测额外解码三秒，给起播时间戳偏移留余量；长测默认跟随实时 HLS 读取；`--pace=realtime` 可额外启用 FFmpeg 的 `-re` 限速用于对照。检查音视频轨、实际解码帧、持续时间、直播序号/追加进度，确认清单没有上游直连地址。

2026-11-07 验收结果记在同目录的 `verification.json`。有代理与无应用层代理两种隔离实例分别检查；直连验收仅在测试子进程中关闭 macOS 自动代理发现，没有更改电脑系统代理。当前网络的官方会话为 US，不能据此推断中国大陆家宽、其他地区或所有未来赛事均可用。长测只代表所列节目在所列时间内的表现。

### 本轮结论

- `npm test` 全链通过；红牛专用回归 13 项通过。
- 配置代理与关闭应用层代理的隔离实例，各 12/12 路通过短测（9 轮播 + 3 当时在播赛事）。
- 代理切换后实际捕获官网、API 和全部媒体主机的 CONNECT；坏代理返回 502，不回退直连，清空后恢复 200。模块关闭后旧主清单与子清单均为 404，开启后恢复 200。
- 网页实播自行车 720p，原生视频处于正在播放且 readyState=4；9 路轮播台标为本机图片，旧单频道不存在。FIP 中心场英／西／德音轨保留，西班牙语单独解码 18 秒通过。
- 长播：综合 723.01 秒、FIP 中心场复测 723.00 秒均正常结束；自行车复测实际解码 720.32 秒，但在测试 14 分钟上限被终止（当时命令额外要求 3 秒余量）。因此三路均达到 12 分钟实际解码目标，但只有两路正常退出，自行车保留超时告警，不能认定当前网络下无缓冲。首次额外 `-re` 限速测试中两路超时，也保留在报告中。后续探测脚本只给短测保留三秒余量，长测按指定时长停止。
- 长测期间媒体清单持续前进，未出现代理登记项过期 404 或上游转发错误。赛事开始／结束变化使用官方响应结构的离线夹具与主项目管理器验证，未声称现场观察到一场比赛完赛。
