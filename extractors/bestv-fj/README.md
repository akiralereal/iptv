# 百视通

`bestv-fj` 默认关闭，需在源管理的独立「百视通」面板中手动开启。部分 IPv4 出口无法播放，因此由用户看过网络要求后按需使用。未手动设置过的用户随新默认值关闭；已手动开启或关闭的配置保持原样。开启后在独立「百视通」分组输出预选的七路专业频道；可在「加入订阅的频道」中选择完整 64 路里的其他频道。不会自动把这 64 路全部加入订阅。

| 多彩文体4K | 219 | 有；本次实际视频为 1080p |
| 都市剧场 | 220 | 有 |

| 乐游 | 225 | 官方空表 |
| 法治天地 | 226 | 官方空表 |

2026-10-29 核对咪咕官方各分类目录及项目其他固定模块，这七路没有现有来源；快乐垂钓、嘉佳卡通已有，因此默认不选。这个默认选择是固定的，之后用户添加其他来源时不会悄悄改动勾选。

## 来源

研究入口为用户提供的 `bst_LW2MB/index.php` 与频道表，原件和媒体验证保存在相邻 `tv-lab/bestv-fujian-live-lab`。主项目实现独立维护，不执行 PHP，也不依赖实验目录或本地 1936 服务。

- 匿名设备报备：`https://kylinapi.bbtv.cn/5g/v1/client-id-by-region`，按样本中的 SDK 请求签名取得 clientID。
- 官方目录及频道台标：同域 `/5g/v1/tvs`，台标来自目录 `icon` 指定的 `tvappstatic.bestv.com.cn/images/`。东南卫视在福建、卫视两组重复，元数据一致时只保留一次，矛盾时失败。
- 当前播放：`/5g/v1/tv/now/{id}`。只接受 ID、台名匹配、`state=live`、明确 `paid=false` 或 `contentIsFree=true`，且具有足够有效期的响应。`contentIsFree=false` 与会员 benefit 字段同时出现过，不能把匿名能取到 URL 等同于长期免费承诺。
- 官方节目单：`/5g/v1/tv/programs/{id}`，返回跨日编排；按北京时间取今明两天，清理占位、重复及重叠。只为默认七路登记 EPG；其他 57 路没有本模块独立节目单，可由同时开启的已有来源提供同名节目单。

目录允许范围为此前实际解码通过的 64 个 ID，旧新疆卫视 ID 205 的 API 为 404，排除；ID 214 正常。目录后来新增的其他频道不自动收录。宗教频道不收录。TLS 证书校验保持开启；官方停用、付费或未知结构会失败，保留失败原因供源管理查看。

## 地区版目录

`client-id-by-region` 按请求出口所在地区发 clientID，`/tvs` 随之返回不同版本。2026-10-29 用 Globalping 探针实测：多数出口（武汉联通、上海移动 AS56040、香港，以及腾讯云、上海联通的 IPv6）拿到上面说的「央视／特色／福建／卫视」四组 69 行；镇江的上海移动出口（AS24400）拿到「上海／正在直播／上海直播间／特色／卫视…」13 组，没有多彩文体4K、动漫秀场、乐游、法治天地，用那份 clientID 请求 `/tv/now/219`、`/tv/now/222` 也拿不到地址。都市剧场、东方财经、生活时尚在多个分组里重复，但元数据一致，可以正常去重；这三路的播放地址在 `dongfang5g-pc-v52-live.bestvcdn.com.cn`，路径、清单格式和 TS 分片与福建节点相同，实测能取到清单和分片。美国、日本出口连接 API 超时。

因此目录里没有的选中频道只跳过，并在模块详情写明跳过了哪些；所有选中频道都不在目录里时才算抓取失败。同一 ID 元数据互相矛盾仍然失败。

## 2026-10-30 跨出口复测

- 本机原环境（后续确认启用了 Shadowrocket TUN，不能称为物理直连）：模块全部 64 路通过实际 8 秒音视频解码和直播序号增长，48 路 1080p、16 路标清。
- 上海版身份：模块范围内目录可见 36 路，28 路不在当前目录中。修正下述免费标记判断后，36 路均通过本机媒体解码与直播增长检查；默认七路中仍只有都市剧场、东方财经、生活时尚三路可见。
- 三路默认台用上海联通 AS17621 同一探针重新报备、取播放地址、读清单和下载 TS，清单均为 200、分片为 206；相同地址返回的媒体在本机完成 8 秒音视频解码并核对节目画面。最初的镇江上海移动 AS24400 身份也通过三路检查，后续该探针离线，使用上海联通再次确认。
- 武汉联通 AS4837、深圳移动 AS56045：默认七路均从同一真实探针完成报备和取流 API 请求，API 正常但七路新签名清单全部为 403；相同地址用相同 User-Agent 在本机为 200。上海移动 AS56040、宁波 AS136188、广州腾讯云 AS45090 的生活时尚清单同样返回 403；香港样本还出现清单 200、分片 403。

这些结果说明“目录存在、API 返回地址”不能作为跨出口可播放的证明。403 的差异发生在 CDN 媒体链路，不能仅凭本机结果承诺其他地区可用，也不能将探针样本扩大成整个省或整个运营商的结论。NAS 本身访问 CDN 被拒绝时，全代理也不会恢复这条链路。

本轮还发现上海版 12 路公开频道返回 `paid=true`、`contentIsFree=true`，且提供正常官方直播；原逻辑只接受 `paid=false`，把它们误拦。现在接受官方明确标为免费的情况，未标免费且 `paid=true` 的响应仍拒绝。已对这 12 路逐路完成实际解码复测，回归测试也覆盖该组合。没有构造地区参数或更改会员、付费、加密响应来恢复被拒绝的网络出口。

原始去敏报告、快照及复测脚本保存在相邻实验目录 `bestv-fujian-live-lab/reports/region-audit-2026-10-30/`。其中上海版三路是探针实取清单/分片再本机解码；其余 33 路上海版可见频道主要是使用真实上海版 clientID 的本机媒体验证。探针不运行 FFmpeg，不能将其表述成远端播放器已经长播通过。

## IPv6 播放网络（v4.54.0 起）

2026-10-30 后续对照发现了地址族差异：同一武汉联通 AS4837 探针，IPv4 的生活时尚清单为 403；IPv6 从同一真实探针完成正常报备、取址、读清单和 TS 请求，返回 HLS 200、TS 206，仍是原来的 `fjnetv51.live.bestvcdn.com.cn`，未替换身份、区域或签名字段。本机物理 `en0` 原生 IPv6 的默认七路也已实际解码通过。

在「源管理 → 百视通 → 播放网络」增加两种模式：

- **默认网络**：保持已有行为，遵循应用层代理设置，通常只转发清单。
- **IPv6 直连并转发视频**：报备、目录、取址、HLS 和 TS 都用服务器的 IPv6 连接官方域名；清单及媒体经本机转发，IPv4 播放器无需访问 IPv6 CDN。切换后旧 `/relay/` 和无后缀地址也会得到本机媒体引用，避免旧订阅将 TS 交给电视直连。IPv6 失败会明确失败，不静默落回已知可能 403 的 IPv4，也不会 302 到播放器无法访问的上游。

此模式不使用应用层 HTTP(S) 代理，但不会关闭系统 VPN/TUN；本机启用隧道时，操作系统仍可能接管流量。实现保留官方域名、正常 DNS 和 TLS 证书校验，不固定 CDN IP、不修改授权数据。上游地址族随主清单、嵌套清单、TS、HEAD 和 Range 一起传递，IPv4 与 IPv6 分片引用分开登记。

### Docker 检查

更新到 v4.54.0 及以上镜像后，在容器内部运行只读检查：

```sh
docker exec iptv node scripts/probe-bestv-network.mjs auto
docker exec iptv node scripts/probe-bestv-network.mjs ipv6
```

脚本不改配置、不打印 clientID 或签名 URL，检查默认七路的目录、实时 HLS 和 TS 包头，无需 FFmpeg。IPv6 检查通过后，再选择「IPv6 直连并转发视频」，点击模块「立即刷新」，再刷新播放器订阅。视频由服务器转发，会消耗服务器带宽。

仅 NAS 主机有 IPv6 不够，容器本身也必须能通过 IPv6 出网。可为应用配置启用 IPv6 和出站伪装的独立 bridge 网络；本轮 NAS 即通过这种方式接通，保留容器网络隔离。部署者也可按环境选择 host 网络，此时端口映射不生效，应用直接使用主机端口。参考 [Docker bridge 网络](https://docs.docker.com/engine/network/drivers/bridge/)和[Docker IPv6 网络](https://docs.docker.com/engine/daemon/ipv6/)。

播放网络选项旁提供静态使用提示，说明容器 IPv6 出网、仅 IPv4 播放器的使用方式、服务器转发带宽和出口差异；不会在用户切换选项时自动发起网络检测。

后续验收：本机物理 IPv6 出口全部 64 路通过约 8 秒音视频解码；实际 NAS 使用上述 IPv6 bridge 和本地构建镜像，默认七路经正式服务全部完成约 30 秒音视频解码、无解码错误，直播序号持续前进。深圳阿里云 AS37963、广州腾讯云 AS45090 的 IPv6 探针也分别从同一探针完成正常报备及默认七路的取址、HLS 200、TS 206 与同步字节检查；远端探针不执行音视频解码。本轮深圳移动没有可用 IPv6 探针，不能把它记为上游拒绝。

这是一条经过实测的可选路径，不代表所有地区、运营商和 IPv6 节点都可用；云网络结果不能扩大为当地所有家宽通过。只具备 IPv4 的部署，暂未找到已验证的通用修复。

## 取流与续签

默认网络的订阅输出 `/relay/bestv-fj-<id>.m3u8`；IPv6 模式输出 `/proxy/bestv-fj-<id>.m3u8`。每次播放器刷新直播清单都会调用本模块：clientID 最多缓存 420 秒，播放入口最多缓存 120 秒且预留至少 30 秒余量；实时清单每次都读取。CDN 在缓存期内提前拒绝入口时立即重新获取，API 返回 401/403 时重新报备一次，仍失败就结束，不返回过期清单。

模块直接返回已经校验的实时媒体清单，相对分片由主项目改成绝对地址。媒体限定到 `fjnetv<数字>.live.bestvcdn.com.cn` 或 `dongfang5g-pc-v<数字>-live.bestvcdn.com.cn`（上海版目录的播放节点）下当前频道的签名目录，拒绝跨频道、外部主机、加密、点播及未知清单结构。签名、clientID 和完整播放 URL 不写入磁盘频道缓存或错误描述。

默认只转发清单，播放器直连视频分片，因此服务器与播放设备都要能访问百视通。`?relay=2` 订阅可切换到主项目现有全代理模式。全代理会占用部署机器的媒体带宽。地区、运营商、平台状态和播放器兼容性仍可能影响播放；自动更新入口也不能消除所有网络故障。

测试夹具裁剪自 2026-10-29 实际官方目录和节目单，播放地址使用合成签名目录。验证默认开关、64 路选择、目录停用与变化、媒体边界、播放和 clientID 过期刷新、CDN 提前失效、付费拒绝及官方节目单处理。

台标已实际下载、检查并生成内置备份。平台的生活时尚图标为白字透明图，浅色界面文字对比度较低，保留其官方样式。

主项目隔离实例七路均通过 8 秒音视频解码，全代理抽查多彩文体4K 也通过。多彩文体4K 经本机清单入口实际连续解码 **8 分 30 秒**，墙钟 518 秒；34 次独立清单采样均为 200，观察到 6 组签名目录，媒体序号由 179328575 增至 179328625，FFmpeg 无错误输出。短期实测已跨过 120 秒播放地址缓存和 420 秒 clientID 缓存窗口；尚不能据此保证跨运营商或全天长播。详细记录保存在实验目录 `reports/main-long-play.json`。
