iPTV 是一个面向家庭影音与 NAS 用户的**模块化 IPTV 直播源管理与分发系统**。它内置央视频、咪咕、B站、抖音、虎牙、斗鱼及多地区广电等抓取模块，也能接入需要网页解析的内置源、维护者筛选的公开独立源、自定义直连地址和 M3U/TXT 订阅；所有来源统一完成聚合、去重、编排，再输出干净的播放列表与 EPG 节目单。

项目更新和社区公告请订阅 [Telegram 公告频道（@iFansClub）](https://t.me/iFansClub)；使用问题、反馈和心得交流，欢迎加入 [Telegram 用户交流群（@iFansClubChat）](https://t.me/iFansClubChat)。Bug 反馈和功能建议也可以提交 [GitHub Issue](https://github.com/akiralereal/iptv/issues)。

> [!IMPORTANT]
> 本项目是自托管的软件工具。除项目自制的使用公告短片外，不托管第三方音视频节目；仓库及运行时可能整理互联网上公开可访问的播放地址与频道元数据，但“公开可访问”**不代表内容属于公有领域，也不代表已获得复制、转播或商业使用授权**。请仅在获得合法授权的范围内使用；如你是权利人并认为相关条目侵权，请按[版权与侵权处理](#-版权与侵权处理)提交下架通知。

## 🚀 快速开始

推荐使用 Docker Compose。只需要一个配置文件和一条启动命令，几分钟即可拥有自己的 IPTV 服务。

**Docker 镜像：[`akiralereal/iptv`](https://hub.docker.com/r/akiralereal/iptv)** · [查看版本标签](https://hub.docker.com/r/akiralereal/iptv/tags)。下面使用 `latest` 标签；使用 NAS 图形化容器管理器时，也可直接搜索 `akiralereal/iptv`，按下方配置设置端口和数据目录。

### 1. 创建配置文件

创建 `docker-compose.yml`：

```yaml
services:
  iptv:
    image: akiralereal/iptv:latest
    container_name: iptv
    init: true                    # 回收 Chromium 僵尸进程
    ports:
      - "1905:1905"
    environment:
      - mport=1905                # 容器监听端口，与 ports 对应
      # - mhost=                  # 可选：外部访问地址（如 http://192.168.1.100:1905）
      # - mpass=                  # 可选：访问密码，设置后访问 http://ip:port/密码/...
    volumes:
      - ./data:/iptv/data         # 数据持久化，不挂载则重建容器 / 升级镜像会丢配置
    restart: always
```

### 2. 启动服务

```bash
docker compose up -d
```

升级时执行：

```bash
docker compose pull && docker compose up -d
```

### 3. 打开管理后台

部署完即可访问：

| 用途 | 地址 |
| --- | --- |
| M3U 播放列表 | `http://your-ip:1905/interface.m3u`（推荐带 `.m3u` 后缀；裸 `/m3u` 内容相同） |
| TXT 播放列表 | `http://your-ip:1905/txt` |
| EPG 节目单 | `http://your-ip:1905/playback.xml` |
| **管理后台** | `http://your-ip:1905/admin`（设了密码则 `http://your-ip:1905/密码/admin`） |

> 🧩 平台账号、画质等内容配置**不用写进 compose**：部署后进后台「**🌐 源管理**」在对应模块卡片里设置（支持扫码登录 / 书签工具），保存即时生效。备份 / 换机迁移用后台「设置 → 备份迁移」一键导出导入（`logos/` 自定义台标需单独拷贝），或直接备份 `./data` 目录。更多环境变量与玩法见[配置与进阶](#-配置与进阶)。

| 播放器 | 推荐订阅 |
| --- | --- |
| DIYP / 百川影音 | TXT 订阅：`/txt` |

## ❓ 常见问题

<details>
<summary><b>服务部署在香港或海外，或者播放设备挂了代理，哪些频道能看？</b></summary>

模块的默认开关不看网络：大部分模块默认开着，「海外频道」「澳门」默认关着，需要的在后台「🌐 源管理 → 内置抓取模块」最下面的「海外」小节里打开；部署在海外时，用不了的模块也在这里关掉。

能不能播，要看取流时是谁去连官方：

1. **服务端取流**（换签、全代理、中继清单）：看部署服务的机器（NAS / VPS）的网络。咪咕、安徽、重庆、贵州、泉州、山东、深圳、青海、新疆只对大陆开放；吉林、江苏、无锡对大陆和香港开放，部署在其他海外地区时用不了。其中服务端只换签或只中继清单的，视频还要播放设备能连上。
2. **播放器直连**（服务端只给地址）：看播放设备（电视、盒子、手机）的网络。「海外频道」33 台都是这种，在大陆连得上但常卡顿，播放设备挂了代理就流畅；宁夏（只对大陆开放）、黑龙江（大陆和香港）也是这种。
3. **两头都要**：「澳门」播放前服务端要向官网查 CDN，视频再由播放器直连，部署的机器和播放设备都要能连到大陆以外。
4. 央视和卫视在海外靠「央视频」：63 个公开频道里 58 个能播，CCTV5、5+、16 按体育版权不对海外开放。

各模块在海外的实测结果见 [OVERSEAS.md](OVERSEAS.md)。

</details>

<details>
<summary><b>iPanda 网页端可以选“超清”，为什么这里只有 720p？登录能解锁 1080p 吗？</b></summary>

iPanda 网页播放器的清晰度名称与实际分辨率依次是：流畅 `640×360`、标清 `854×480`、高清 `1024×576`、超清 `1280×720`。播放器把 1080p 另称为“蓝光”，但当前 22 路 HLS 均未提供该档；逐路检查最高档视频编码也都是实际 `1280×720`，不是清单虚标。

这些频道的匿名接口已经返回公开可播状态，页面没有启用 VIP 清晰度限制。登录不会为当前 iPanda 直播解锁 1080p；主项目检测到的最高档 720p 正好就是播放器菜单中的“超清”。两个 24 小时总频道提供上述四档，其余 20 路为单档 720p。

</details>

<details>
<summary><b>北京台为什么只看到慢直播？怎样启用 9 个电视频道？</b></summary>

北京时间的公开活动和慢直播不需要登录，会自动出现；北京卫视、BRTV 各地面频道与卡酷少儿需要本人站点登录态。进入「🌐 源管理 → 北京广播电视台」，按卡片里的入口打开站点并登录；在浏览器开发者工具的 Network（网络）里刷新页面，点开 `getUserInfo` 请求，在 Request Headers 中单击 `Cookie` 的值后按 ⌘C（Windows/Linux 按 Ctrl+C），粘贴回后台保存即可，不需要鼠标右键。也可以用 `mBtimeCookie` 环境变量配置。

模块会先验证 Cookie：有效时加入 9 个电视台，失效时只隐藏电视台并给出提示，免登录直播继续可用。凭据只发给北京时间账号 / 取流接口，不会写进订阅或发送给媒体 CDN。北京时间媒体要求源站防盗链请求头，因此该模块固定由服务端代理 HLS；本地 macOS 会自动沿用系统 HTTPS 代理，Docker / Linux 可按需设置标准 `HTTPS_PROXY` 环境变量。

</details>

<details>
<summary><b>凤凰卫视怎样开启 720p？需要付费会员吗？</b></summary>

进入「🌐 源管理 → 凤凰卫视」，导入本人凤凰秀账号的 `App.user.token` 后保存即可。支持粘贴 Token 值或包含它的完整 Cookie；模块内提供书签工具和获取步骤，也可用 `mFengshowsToken` 环境变量配置。保存后的凭证随主项目配置持久保留，重启无需重填；失效时重新获取。

2026-09-03 实测：**游客三台均为 854×480；普通账号登录后三台均为 1280×720、25 fps、H.264，无需付费会员**。接口档位叫 `fhd`，实际是 720p。

本模块只提供凤凰资讯、凤凰中文、凤凰香港三路直播，不接入回看、点播、活动直播或栏目目录。三台归入香港分组；其它来源（内置精选列表、外部订阅）提供的同名凤凰条目不会被顶掉，原样保留作备用线路；播放器按名聚合「源1 / 源2」时本模块源排在前面，即默认源。播放地址实时向上游获取，沿用地区调度，Token 不发送到媒体 CDN 或写入订阅。直播使用 HTTP-FLV，本机仅转发不转码；网页播放器已支持，外部播放器也需支持 HTTP-FLV。

</details>

<details>
<summary><b>后台有央视频、虎牙、斗鱼，LunaTV 却导入不到？</b></summary>

<br>

部分 LunaTV / MoonTV 版本只把 `#EXTINF` 紧接的下一行当播放地址，遇到中间的 `#EXTVLCOPT:network-caching` 缓冲提示会漏掉整个频道（issue #114）。本项目的 M3U 输出已省略仅含缓冲提示的选项块，也兼容升级前的频道缓存。运行包含此修复的版本后，在 LunaTV 管理后台刷新直播源即可，订阅地址无需更换；缓冲时长由播放器自行设置。

B 站直播已与虎牙、斗鱼一样改为播放时解析、由本机中继清单，不再依赖 `#EXTVLCOPT` 请求头。其它来自订阅的直连源若带 `Referer` / `User-Agent`，那是播放所需的请求头，仍会保留；若使用的 LunaTV 版本不能解析并传递这些选项，这类频道需要在客户端侧适配，不能靠删除请求头或切换 `relay=1/2` 修复。

</details>

<details>
<summary><b>某些播放器点开频道后只有声音、没有画面？</b></summary>

<br>

这通常是 **H.265（HEVC）兼容性**问题：部分平台的直播流默认使用 H.265，而播放器无法解码。进入「🌐 源管理」，打开对应模块的配置并取消「启用 H.265 原画」，保存后重新播放。通过环境变量部署时可设 `menableH265=false`；个别频道仍有问题时再设置 `menableHDR=false`。

</details>

<details>
<summary><b>频道和台标正常，但播放一直转圈？</b></summary>

<br>

播放器可能不跟随 302 跳转。进入「我的频道」，点击订阅地址旁的「🩹 兼容版」，将新地址重新添加到播放器即可。兼容版由服务器直出播放清单，视频仍由播放器直连 CDN，不占用服务器的视频转发带宽。

</details>

<details>
<summary><b>隐藏掉的频道过几天又自己冒出来了？</b></summary>

<br>

「隐藏」绑的是频道 ID，而 ID 是按播放地址算的——源换了地址，那条隐藏就失效了。带签名 / 有效期参数的地址（`?expire=…&sign=…`）已经不再影响 ID；换了路径或域名的仍会。想让某个台**以后都别出现**，用「我的频道」里频道旁的「屏蔽」按钮，或右上角「🚫 屏蔽规则」按名字配一条：规则只看名字，源换址、频道每天重建都照样生效，删掉规则即恢复。像「体育-昨天 / 今天 / 明天」这类每天重建的分组，逐条隐藏没有意义，对其中一个分组点「隐藏分组」时会提议把同前缀的一起隐藏，以后新出现的也自动挡掉。

</details>

<details>
<summary><b>台标或节目单缺了一些，怎么补？</b></summary>

<br>

**台标**：用频道自己的官方台标，由本机托管（服务端下载校验后从你自己的服务器提供，坏图自动换下一个来源）；官方图取不到、或 m3u 本来就没写台标的，用仓库自己维护的内置台标（`logo-pack/`）兜底，不联网。默认不再引入别人维护的公共台标库，想用的话自己设 `mexternalLogoBase`，规则见 [LOGO.md](LOGO.md)。都没有的会留空（播放器画自己的占位图，不再裂图）。点「我的频道」右上角「🖼 缺台标」可以列出当前档里所有没图的频道，逐个点进详情上传；或直接把 `<频道名>.png` 放进数据目录的 `logos/`，优先级最高。景观、慢直播这类本来就不是台名的，留空即可。

**节目单**：按「咪咕自带 → 各模块从官方接口取 → 外部 EPG 源」的顺序补，前面给了的频道后面不再覆盖。模块自带节目单目前接入了央视频（央视与卫视频道），河南、浙江、江苏、广东、深圳、广西、海南、山西、陕西、天津、上海、山东、河北、大连、南京、湖北、福建（含厦门、福州）、新疆、云南、宁夏、泉州（新闻综合、闽南语）、石狮新闻综合频道、莆田新闻综合与文旅生活、无锡 5 个频道、扬州 4 个频道、南通三套电视、江门综合、青岛 5 个频道、绍兴三套电视的官方节目单，北京（7 个电视频道）、甘肃卫视、延边卫视、青海卫视、成都新闻综合与成都公共取自央视网，以及凤凰卫视、香港卫视、澳门莲花卫视、澳广视 6 个电视频道、NHK World、YTN；湖南、内蒙古、甘肃地面频道、吉林（延边卫视以外）、四川、成都其余频道、贵州、重庆、黑龙江、广州、辽宁北斗、江西、安徽、西藏、青海（青海卫视以外）、嘉兴、杭州、宁波、台州天台、梅州、晋江、仙游、宁德官方暂时没有可用的节目单。咪咕频道（CCTV 各台取自央视网）与多数模块取今明两天；部分省台官方只发当天的节目单，零点后要等下一轮更新才有新一天的。各模块节目单的来源、覆盖与没接上的原因见 [EPG.md](EPG.md)。外部 EPG 源默认不带：先后内置过的 51zmt 已退化到只剩央视卫视，erw 10 月 1 日起停止免费下载。需要更广的覆盖，可在「设置 → EPG 聚合」自己加 XMLTV 源；某个源想压过官方节目单（比如它给的天数更多），勾上「优先于官方节目单」，它当前有节目的频道就改用它，源停更只剩旧数据时自动让回官方。老部署里没改过的内置默认源会被自动删掉；改过名的那条程序不会动，列表里会有一行提示。精选列表里的港台频道、各地景观和 B 站 / 虎牙 / 斗鱼这类没有公共节目单，属于正常。广东体育赛事子频道也按直播间处理，赛事标题直接显示在频道名中，不套用广东体育电视频道的节目单。

<details>
<summary><b>使用兼容版后仍然无法播放？</b></summary>

<br>

再切换到「🚚 全代理版」，即 `/interface.m3u?relay=2`。对明确支持服务端代取的频道，它会把清单地址改为本机同源地址并由服务器转发视频分片，能兼容更多老旧或限制较多的播放器；若上游平台不允许服务端拉取分片，则保留该模块的安全播放模式。视频流经服务器会增加带宽占用，因此能使用标准版或兼容版时，不建议开启全代理版。

</details>

<details>
<summary><b>央视频会员频道怎样登录？登录后会不会很快失效？</b></summary>

<br>

63 个公开频道不需要登录，服务会在真正播放时动态取票、自动续签短效地址，并在主线路异常时切换备用 CDN。

另有 10 个会员频道会一并出现在播放列表中。两种登录方式任选其一：

- **服务在有桌面的电脑上跑**：在那台电脑上用 `localhost` 打开后台，进入「🌐 源管理 → 央视频」，点击卡片里的央视频登录按钮，在弹出的窗口完成本人账号登录即可。
- **Docker / NAS 等没有桌面的部署**：在自己电脑的浏览器登录央视频网站，按 F12（Mac 按 ⌥⌘I）打开开发者工具切到 Network，刷新页面，点开任意一个 `yangshipin.cn` 的请求，在 Request Headers 里单击 `Cookie` 的值后按 ⌘C（Windows 按 Ctrl+C）复制，粘贴到「🌐 源管理 → 央视频」卡片的导入框并「导入登录态」。必须从请求头复制：央视频的会话 cookie（vusession、accesstoken 等）是 HttpOnly，网页脚本和书签工具读不到，只有请求头里才有完整的一套。服务端会把这组 cookie 种进自己的浏览器 profile 并让站点 SDK 当场校验，成功后显示昵称与 VIP 状态；「公告」分组里的教程短片演示了全过程。

服务不接收密码；导入的 cookie 只存在央视频专用的 Chromium profile 里，不写进配置文件或备份。站点 SDK 的刷新令牌 48 小时有效、由 SDK 在页面里自动续期，服务端每 6 小时静默拉起一次后台会话让它续一次，家里几天没人看会员频道也不会掉线；站点要求重新验证、账号退出或会员到期后，需重新登录或导入。导入后如果你自己电脑上的登录被踢下线，属于正常现象（同一份令牌被服务端接管），不影响电视端。

会员视频必须经网页播放器解扰后才能被普通 IPTV 客户端正确解码，因此播放期间服务端会运行 Chromium，并在内存中保留最近少量 H.264/AAC fMP4 片段。最多同时保留 3 个会员频道，3 分钟无人请求后释放，换台后切回来不用重新起桥；每路起播前先攒够约 18 秒（至少三个分片）再交给播放器，并催官网播放器立即续拉后续分片；VLC 内核的播放器（Ceau Player、VLC 等）会拿到专门的清单，避免它开播几秒就卡一下。首次自动登录目前只支持有桌面环境的本机运行：Docker/NAS 无法把服务端窗口弹到你的电脑，管理页会明确禁用该按钮。浏览器 profile 等同账号凭据，不包含在 JSON 配置备份中，换机或跨平台部署请重新登录。

</details>

<details>
<summary><b>央视频频道能回看吗？节目单里点回放怎么还是直播？</b></summary>

<br>

不能，央视频模块只做直播。它的频道在订阅里已明确标为 `catchup="none"`，支持该约定的播放器（TiviMate、OTT Navigator、Kodi IPTV Simple 等）不会再给这些频道显示回看入口；节目单本身不受影响。

要回看同一个台，切到播放器里同名频道的咪咕线路（播放器按名聚合「源1 / 源2」时选咪咕那一路），咪咕源的回看链路是现成的。不单独给央视频做回看，是因为央视频回看按频道和时段受版权方限制（如 CCTV13 全时段不提供），做出来体验也是时好时坏。

</details>

<details>
<summary><b>服务卡死、硬盘不停读写，日志里反复出现「开始提取」「Navigation timeout」「浏览器会话已启动」？</b></summary>

<br>

这是多个无头 Chromium 同时在跑把机器（尤其是内存 ≤2G 的 NAS / 小主机）拖进了交换分区。网页抓取型的源（如纬来体育）、广东台续签、央视景观、湖北台防盗链都需要起一个 Chromium，每个约占 200~400MB；此前它们各自启动、互不知情，且一个当前抓不到的源会在每个 5 分钟检查里都重新起浏览器再试一遍。

现已改为：全进程共用一个启动器，同时存活的 Chromium 不超过 `mbrowserConcurrency`（默认 2，超出的排队，常驻会话空闲时会主动让位）；抓取失败按 10 → 20 → 40 分钟指数退避，不再每 5 分钟重试；网页抓取时不下载视频分片、图片、字体，取票会话也拦掉图片、字体（央视景观、湖北台连媒体请求一并拦掉；广东台的页面须保持在线，否则源站会立刻作废刚发的票据），并关闭 Chromium 磁盘缓存，5 分钟无人取票就整个关掉浏览器。若机器内存很小，建议在 compose 里设 `mbrowserConcurrency=1`；不需要网页抓取的可直接在「🌐 源管理」关闭对应的源或模块。反过来，若你经常**同时**观看广东、湖北、央视景观里的多路频道（这三个模块各需要一个常驻浏览器），内存又够（4G 以上），可设 `mbrowserConcurrency=3` 避免它们互相让位、反复重启浏览器。

想在本地几分钟内验证这套机制：`msourceTickSeconds=20 mbackoffBaseMinutes=0.5 node app.js` 可把 5 分钟检查周期与 10 分钟退避基数压缩（仅供测试，生产不要设）；`node scripts/verify-browser-launcher.mjs` 会用本机模拟直播页跑一遍并发上限 / 空闲让位 / 分片拦截 / 失败退避。

</details>

<details>
<summary><b>央视景观需要登录吗？为什么日志显示浏览器会话已启动？</b></summary>

<br>

不需要登录。日志中的「央视直播中国浏览器会话已启动」表示服务端启动无界面的 Chromium，执行央视网页播放器并获取临时 HLS 地址，不会打开登录页，也不会保存央视账号或 Cookie。若相邻日志出现「数字频道号 + 由于版权原因，请登录后观看」，该数字频道号属于咪咕，与央视景观无关。

央视 CDN 会同时校验播放清单和视频分片的源站请求头，普通播放器无法自行补齐，因此央视景观固定使用全代理：只有实际观看时才产生流量，单路常见约 1–3 Mbps，多个观看设备会叠加。升级后请重启服务或重新生成播放列表，并在播放器中刷新订阅；若解析失败，服务日志会明确显示「央视直播中国链接请求失败」及具体原因。

</details>

### 📺 多套配置档（给不同电视各一套）

后台「📺 我的频道」标题行右侧可新建 / 切换配置档，每档独立维护隐藏 / 分组 / 排序 / 重命名，互不影响；每台电视填各自的地址（每档底部可复制），如 `http://你的IP:1905/interface.m3u?profile=woshi`。各档共享同一份底层频道与 EPG，新增电视不增加抓取成本；默认档地址不变、老用户零感知。

### 🧹 空白部署 / 纯频道管理

只想用自己的源时，用内容开关关掉自带内容（也避免同名分组撞车）：

| 需求 | 配置 |
| --- | --- |
| 彻底空白，自己加源 | `mblank=true` |
| 空白但保留抓取核心 | `mblank=true` + `menableMigu=true` |
| 只去掉自带的额外源 / 订阅 | `menableBuiltInSources=false` + `menableBuiltInSubscriptions=false` |

也可在后台「🌐 源管理」直接开关各卡片，保存即时生效。关闭 `menableMigu` 后体育赛事、回看与对应 EPG 不可用，属预期表现。

### 📡 公网地址 (mhost)

反向代理 / 域名访问 / 对外分享时填写（如 `http://yourdomain.com:1905`），仅内网使用留空即可。系统自动按访问来源选择播放列表里的地址：内网访问用内网地址，反代访问（带 `X-Forwarded-For`）用配置的公网地址；填 `http(s)://` 完整地址时不会强制补端口。

### 🔐 访问密码 (mpass)

设置后所有服务都要在 URL 带密码路径：`http://ip:port/密码/interface.m3u`、`http://ip:port/密码/admin` 等，播放列表内的频道链接自动注入密码路径，未授权访问返回 403。

### 🔧 本地运行（不用 Docker）

需要 Node.js 20+（推荐 22 LTS）；部分平台的频道需要中国大陆网络环境。

```bash
git clone https://github.com/akiralereal/iptv.git && cd iptv
node app.js
```

环境变量与 Docker 同名同义，例如：`mport=1905 mhost="http://localhost:1905" node app.js`（Windows PowerShell：`$Env:mport=1905; node app.js`）。
