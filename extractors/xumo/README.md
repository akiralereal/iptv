# Xumo Play

从 Xumo 官方网页目录及 `valencia-app-mds.xumo.com` 公开播放接口获取直播。由独立实验台原生移植到主项目，运行不依赖实验台进程、Python 服务或社区 IPTV 列表。

## 使用

在「源管理 → 内置抓取模块 → 海外 → Xumo Play」开启，默认关闭。使用主项目原有 M3U 订阅即可，频道按 `Xumo · 官方分类` 分组，稳定入口为 `/proxy/xumo-{频道ID}.m3u8`，例如 UFC 为 `/proxy/xumo-99951134.m3u8`。台标来自 Xumo 官方频道图像服务，并使用主项目的台标托管机制。

目录、取址、主清单、子清单、视频、音轨、字幕和密钥均使用主项目 `outboundFetch`。在「设置 → 网络代理」配置 HTTP/SOCKS 代理；没有填写时沿用环境或系统代理，都没有时按服务器路由直连。播放设备始终连接主项目，视频会占用服务器带宽及代理流量，播放不转码。网络代理探测名单和域名说明从模块声明自动生成。

默认选择最高分辨率，同分辨率优先帧率，再比较平均和峰值码率；对应音轨、WebVTT 字幕和 CC 字幕声明保留。字幕选项取决于频道与播放器能力。开启代理后字幕同样从主项目读取。地址或代理出口变化后重新解析；播放会话仅短暂缓存 5 秒以合并并发，不写入订阅或持久快照。

## 自动维护

- 每 24 小时刷新官方频道和入口，每 6 小时检查主清单、最高档媒体清单与独立音轨。
- 主项目每轮源刷新检查调用模块，模块仅在到期时联网。全量维护分批在后台执行，最多 8 路并发，不占住主项目抓取超时；新结果在下一轮源刷新时合并到订阅。主项目默认每 5 分钟检查一次到期任务，因此实际执行有一个检查周期的误差。
- 新频道或变更入口先下载媒体样本、使用 FFmpeg 解码并确认直播时间线推进，通过后发布。FFmpeg/ffprobe 已加入 Docker 镜像依赖；源码运行需在 PATH 中提供，或设 `FFMPEG_BIN` / `FFPROBE_BIN`。外部工具仅读取本地样本，不绕开网络代理取流。
- 初始自带 2026-11-08 验证的 422 个非宗教频道。目录读取失败、目录骤减超过 30%、已有频道通过率不足 70% 时，保持上一有效快照。个别失败保留原频道并记录状态；失败从 30 分钟起退避重试。
- 频道下架须经过两次有效目录且间隔至少一天。宗教排除在发现、快照读取和播放时持续执行，含 11 个已核对 ID 及新频道名称、介绍和分类过滤。DRM、没有独立 HLS 直播的频道不新增。
- 数据位于主项目数据目录：`xumo-state.json`、`.previous` 备份和 `.runtime` 任务状态；原子替换写入。更新失败不覆盖有效快照，损坏时先恢复备份，再使用已验证种子。
- 模块关闭后，主项目停止触发维护；在飞任务在下一次请求前检查开关，不发布关闭后的结果。订阅移除频道，旧频道、子清单及分片入口也返回不可用。

Local Now 使用 Xumo 官方资产中的默认 ZIP，不替换为用户位置。官网已有的当前节目字段与完整逐日 XMLTV 属于不同接口，本模块本次保持原独立模块的直播范围，尚未接入 XMLTV。新源的普通 AES 加密样本未实现本地验证时不自动加入，保留旧清单；不处理 DRM。

## 验证

`node scripts/test-xumo.mjs` 覆盖默认关闭、海外分类、代理逐跳校验、字幕/音轨、最高画质、持久调度、失败保留、宗教排除、下架等待、快照恢复与关闭中的任务。已纳入 `npm test`。实际主项目验收记录见 `verification.json`。

2026-11-08 验收：主项目导出 422 路；原生维护核对 451 个官方目录条目，排除 11 个宗教频道，440 个候选中 422 个可用、18 个不加入。422 个频道的媒体/字幕资源域名与 422 张官方台标复核通过；UFC、CBS News 实播 1080p，Local Now 720p，UFC 的 WebVTT 字幕经本机代理读取成功。显式配置网络代理后 UFC 解码 15.015 秒、450 帧；错误代理返回 502，恢复后 200；关闭模块后主清单和已发出的子清单均 404、订阅移除频道。未验证大陆无代理直连，未构建或发布 Docker 镜像。
