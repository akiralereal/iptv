iPTV 是一个面向家庭影音与 NAS 用户的**模块化 IPTV 直播源管理与分发系统**。它内置央视频、咪咕、B站、虎牙、斗鱼及多地区广电等抓取模块，也能接入需要网页解析的内置源、维护者筛选的公开独立源、自定义直连地址和 M3U/TXT 订阅；所有来源统一完成聚合、去重、编排，再输出干净的播放列表与 EPG 节目单。

> [!TIP]
> **v4.3.0 已正式接入央视频**：作为独立源模块，免登录、零配置、默认开启，一次提供 **63 个公开高清频道**，覆盖央视全套、CGTN 多语种和全国主要省级卫视。播放时动态获取短效地址并自动切换可用 CDN，也可随时在「🌐 源管理」中独立关闭。

> [!IMPORTANT]
> 本项目是自托管的软件工具。除项目自制的使用公告短片外，不托管第三方音视频节目；仓库及运行时可能整理互联网上公开可访问的播放地址与频道元数据，但“公开可访问”**不代表内容属于公有领域，也不代表已获得复制、转播或商业使用授权**。请仅在获得合法授权的范围内使用；如你是权利人并认为相关条目侵权，请按[版权与侵权处理](#-版权与侵权处理)提交下架通知。

| **地方频道** | 广东（含广州、深圳）、广西、福建、海南、河北、湖北、辽宁（含沈阳、大连）、南京、青岛、浙江、江苏、山东、河南、上海、湖南等省市卫视与地面频道，并持续接入更多地区 |
| **景观直播** | 央视网「直播中国」当前在线信号，以及美丽河北、Live 南京、青岛城市直播、上海慢直播等官方景观频道；数量随官网在线状态动态变化 |

## 🧩 内容来源与抓取能力

iPTV 的重点不只是一份静态频道表，而是一套可独立开关、可观察状态、可持续刷新的内容接入体系。不同来源采用不同刷新、鉴权与代理策略，平台临时不可达时可在源管理中查看状态或关闭对应模块。

| 来源类型 | 已支持的典型内容 | 工作方式 |
| --- | --- | --- |
| **央视频官方直播** | **63 个公开频道：央视全套、CGTN 多语种、省级卫视** | 独立源模块，免登录、零配置、默认开启；播放时实时生成官方短效地址并续签票据，主 CDN 异常时自动切换备用线路。播放清单由本机中转，视频分片由播放器直连官方 CDN |
| **平台直播抓取** | **B站、虎牙、斗鱼** | 可按分类自动收录当前热门直播间，也可手动指定房间；播放时处理短效地址、画质选择和平台要求的请求头。B站支持扫码登录以使用本人账号可访问的画质，虎牙、斗鱼支持匿名公开直播 |
| **电视与赛事平台** | 咪咕、体育赛事 | 自动整理频道与节目单，并按账号权限、设备兼容性和平台接口状态选择可用画质；需要登录的能力仅使用部署者本人提供的凭据 |
| **凤凰卫视** | **凤凰资讯、凤凰中文、凤凰香港**，归入 **香港**，并置顶到 **亚太** | 仅三个电视直播频道；游客 480p，登录普通凤凰秀账号可获取 **720p / 25 帧，无需付费会员**。后台支持导入 Token / Cookie 并持久保存，播放时取新签名，原始 HTTP-FLV 由本机转发。亚太里其它源（外部订阅、内置列表）的同名凤凰条目不被顶掉，原样排在官方三台之后作备用线路 |
| **官方广电抓取** | 大连、广东、广西、福建、海南、河北、湖北、河南、湖南、江苏、辽宁、南京、青岛、山东、上海、深圳、浙江等 | 从各广电官网、公开接口或客户端公开直播能力获取当前地址；短效签名、防盗链、加密清单和 CDN 代理按模块分别处理 |
| **官方景观直播** | 央视网「直播中国」、美丽河北、Live 南京、上海与青岛城市景观等 | 按官网当前在线状态动态收录；离线、下架或官网调整时会自动减少，不以固定频道数承诺可用性 |
| **内置网页抓取源** | 如纬来体育等需要从公开页面解析当前地址的单频道源 | 内置抓取规则与定时刷新；每个源可配**多个入口地址**，主站打不开或抓不到时自动换备用地址重试，清单本身通过远程配置更新（改仓库文件即生效，无需升级镜像）。每个源均可单独关闭 |
| **精选公开独立源** | 体育、国际、亚太、影视、纪实、音乐、娱乐时尚等 | 项目维护的「精选频道」列表，收集公开可访问且经可用性检查的独立播放地址，并提供远程更新与本地快照兜底；**可访问性检查不等同于版权授权审查** |
| **用户自有来源** | M3U8 直链、网页提取、M3U/M3U8/TXT 订阅 | 完全由部署者自行添加、排序、分组和控制在哪些配置档中显示，适合接入自有设备、合法订阅或已获授权的直播源 |

> [!NOTE]
> 所有内置抓取模块、内置网页抓取源和精选频道都能在「🌐 源管理」中独立关闭；需要完全空白的频道管理器时可使用 `mblank=true`。平台名称及商标仅用于说明兼容性，本项目不隶属于、也不代表上述平台或内容权利人。

## 🚀 快速开始

推荐使用 Docker Compose。只需要一个配置文件和一条启动命令，几分钟即可拥有自己的 IPTV 服务。

**Docker 镜像：[`akiralereal/iptv`](https://hub.docker.com/r/akiralereal/iptv)** · [查看版本标签](https://hub.docker.com/r/akiralereal/iptv/tags)。下面使用 `latest` 标签；使用 NAS 图形化容器管理器时，也可直接搜索 `akiralereal/iptv`，按下方配置设置端口和数据目录。

### 1. 创建配置文件

创建 `docker-compose.yml`：

```yaml
services:
  iptv:
    image: akiralereal/iptv:latest
    container_name: iptv
    init: true                    # 回收 Chromium 僵尸进程
    ports:
      - "1905:1905"
    environment:
      - mport=1905                # 容器监听端口，与 ports 对应
      # - mhost=                  # 可选：外部访问地址（如 http://192.168.1.100:1905）
      # - mpass=                  # 可选：访问密码，设置后访问 http://ip:port/密码/...
    volumes:
      - ./data:/iptv/data         # 数据持久化，不挂载则重建容器 / 升级镜像会丢配置
    restart: always
```

### 2. 启动服务

```bash
docker compose up -d
```

升级时执行：

```bash
docker compose pull && docker compose up -d
```

### 3. 打开管理后台

部署完即可访问：

| 用途 | 地址 |
| --- | --- |
| M3U 播放列表 | `http://your-ip:1905/interface.m3u`（推荐带 `.m3u` 后缀；裸 `/m3u` 内容相同） |
| TXT 播放列表 | `http://your-ip:1905/txt` |
| EPG 节目单 | `http://your-ip:1905/playback.xml` |
| **管理后台** | `http://your-ip:1905/admin`（设了密码则 `http://your-ip:1905/密码/admin`） |

> 🧩 平台账号、画质等内容配置**不用写进 compose**：部署后进后台「**🌐 源管理**」在对应模块卡片里设置（支持扫码登录 / 书签工具），保存即时生效。备份 / 换机迁移用后台「设置 → 系统配置 → 🧳 配置备份 / 迁移」一键导出导入（`logos/` 自定义台标需单独拷贝），或直接备份 `./data` 目录。更多环境变量与玩法见[配置与进阶](#-配置与进阶)。

## 🧭 功能全景

四个页面，完成从内容接入到播放分发的整个流程：

| 页面 | 能做什么 |
| --- | --- |
| **📺 我的频道** | 分组、隐藏、排序、重命名与批量管理；建立多套配置档；复制标准版、兼容版或全代理版订阅地址 |
| **🌐 源管理** | 管理抓取模块、内置源与精选频道；添加网页提取、手动直链或订阅源；检测失效频道并调整多源优先级 |
| **⚙️ 设置** | 调整系统参数、频道别名、自动分组规则、EPG 聚合和用户令牌；导出或导入完整配置 |
| **ℹ️ 关于我们** | 查看当前版本并检查更新 |

修改源后 1-2 秒内自动重新生成播放列表；外部源配置存于数据目录 `external-sources.json`。

### 数据流一览


## 📺 播放器适配

| 播放器 | 推荐订阅 |
| --- | --- |
| DIYP / 百川影音 | TXT 订阅：`/txt` |
| TiviMate / APTV / Kodi / OK 影视 | 标准 M3U：`/interface.m3u` |
| 飞牛影视 | 标准 M3U：`/interface.m3u`，必须保留 `.m3u` 后缀 |
| 极空间极影视、部分老电视盒 | 兼容版：`/interface.m3u?relay=1` |
| 使用兼容版仍无法播放的设备 | 全代理版：`/interface.m3u?relay=2`，视频分片会经过服务器转发 |

> [!NOTE]
> 能使用标准版就无需切换；标准版链路最直接。播放器不跟随跳转时使用兼容版，只有兼容版仍失败时才使用全代理版。
>
> 部分官方模块会按平台要求自动为单个频道启用全代理，与所选订阅版本无关。例如央视景观的 CDN 会校验官网请求头，因此即使使用标准订阅，该分组的清单和视频分片也会自动经过 iPTV 服务端；其他可直连频道不受影响。

## ❓ 常见问题

<details>
<summary><b>凤凰卫视怎样开启 720p？需要付费会员吗？</b></summary>

进入「🌐 源管理 → 凤凰卫视」，导入本人凤凰秀账号的 `App.user.token` 后保存即可。支持粘贴 Token 值或包含它的完整 Cookie；模块内提供书签工具和获取步骤，也可用 `mFengshowsToken` 环境变量配置。保存后的凭证随主项目配置持久保留，重启无需重填；失效时重新获取。

2026-09-03 实测：**游客三台均为 854×480；普通账号登录后三台均为 1280×720、25 fps、H.264，无需付费会员**。接口档位叫 `fhd`，实际是 720p。

本模块只提供凤凰资讯、凤凰中文、凤凰香港三路直播，不接入回看、点播、活动直播或栏目目录。三台归入香港分组，同时置顶复制到亚太分组（找凤凰不用先想它算不算「香港」），两处都在；亚太里其它源提供的同名凤凰条目不会被顶掉，原样排在官方三台之后作备用线路；播放器按名聚合「源1 / 源2」时官方源排在前面，即默认源。播放地址实时向官方获取，沿用地区调度，Token 不发送到媒体 CDN 或写入订阅。直播使用 HTTP-FLV，本机仅转发不转码；网页播放器已支持，外部播放器也需支持 HTTP-FLV。

</details>

<details>
<summary><b>后台有央视频、虎牙、斗鱼，LunaTV 却导入不到？</b></summary>

<br>

部分 LunaTV / MoonTV 版本只把 `#EXTINF` 紧接的下一行当播放地址，遇到中间的 `#EXTVLCOPT:network-caching` 缓冲提示会漏掉整个频道（issue #114）。本项目的 M3U 输出已省略仅含缓冲提示的选项块，也兼容升级前的频道缓存。运行包含此修复的版本后，在 LunaTV 管理后台刷新直播源即可，订阅地址无需更换；缓冲时长由播放器自行设置。

B站等直连源的 `Referer` / `User-Agent` 属于播放所需的请求头，仍会保留。若使用的 LunaTV 版本不能解析并传递这些选项，这类频道需要在客户端侧适配，不能靠删除请求头或切换 `relay=1/2` 修复。

</details>

<details>
<summary><b>某些播放器点开频道后只有声音、没有画面？</b></summary>

<br>

这通常是 **H.265（HEVC）兼容性**问题：部分平台的直播流默认使用 H.265，而播放器无法解码。进入「🌐 源管理」，打开对应模块的配置并取消「启用 H.265 原画」，保存后重新播放。通过环境变量部署时可设 `menableH265=false`；个别频道仍有问题时再设置 `menableHDR=false`。

</details>

<details>
<summary><b>频道和台标正常，但播放一直转圈？</b></summary>

<br>

播放器可能不跟随 302 跳转。进入「我的频道」，点击订阅地址旁的「🩹 兼容版」，将新地址重新添加到播放器即可。兼容版由服务器直出播放清单，视频仍由播放器直连 CDN，不占用服务器的视频转发带宽。

</details>

<details>
<summary><b>使用兼容版后仍然无法播放？</b></summary>

<br>

再切换到「🚚 全代理版」，即 `/interface.m3u?relay=2`。它会把清单地址改为本机同源地址，并由服务器转发视频分片，能兼容更多老旧或限制较多的播放器。代价是视频流会经过服务器，因此能使用标准版或兼容版时，不建议开启全代理版。

</details>

<details>
<summary><b>央视频需要登录吗？为什么没有收录付费剧场频道？</b></summary>

<br>

不需要登录。v4.3.0 收录的是央视频当前可匿名播放的 63 个公开频道，服务会在真正播放时动态取票、自动续签短效地址，并在主线路异常时切换备用 CDN。它是「🌐 源管理」中的独立模块，可以单独查看状态或关闭。

央视频另有 10 个需要登录解锁的付费剧场频道，本项目不收录，也不会要求用户提交央视频 Cookie，或尝试绕过登录、付费及其他访问控制。央视频的播放清单由本机中转，视频分片由播放器直接连接官方 CDN；升级后请刷新播放器订阅，通常无需为该分组切换全代理版。

</details>

<details>
<summary><b>服务卡死、硬盘不停读写，日志里反复出现「开始提取」「Navigation timeout」「浏览器会话已启动」？</b></summary>

<br>

这是多个无头 Chromium 同时在跑把机器（尤其是内存 ≤2G 的 NAS / 小主机）拖进了交换分区。网页抓取型的源（如纬来体育）、广东台续签、央视景观、湖北台防盗链都需要起一个 Chromium，每个约占 200~400MB；此前它们各自启动、互不知情，且一个当前抓不到的源会在每个 5 分钟检查里都重新起浏览器再试一遍。

现已改为：全进程共用一个启动器，同时存活的 Chromium 不超过 `mbrowserConcurrency`（默认 2，超出的排队，常驻会话空闲时会主动让位）；抓取失败按 10 → 20 → 40 分钟指数退避，不再每 5 分钟重试；网页抓取时不下载视频分片、图片、字体，取票会话也拦掉图片、字体（央视景观、湖北台连媒体请求一并拦掉；广东台的页面须保持在线，否则官网会立刻作废刚发的票据），并关闭 Chromium 磁盘缓存，5 分钟无人取票就整个关掉浏览器。若机器内存很小，建议在 compose 里设 `mbrowserConcurrency=1`；不需要网页抓取的可直接在「🌐 源管理」关闭对应的源或模块。反过来，若你经常**同时**观看广东、湖北、央视景观里的多路频道（这三个模块各需要一个常驻浏览器），内存又够（4G 以上），可设 `mbrowserConcurrency=3` 避免它们互相让位、反复重启浏览器。

想在本地几分钟内验证这套机制：`msourceTickSeconds=20 mbackoffBaseMinutes=0.5 node app.js` 可把 5 分钟检查周期与 10 分钟退避基数压缩（仅供测试，生产不要设）；`node scripts/verify-browser-launcher.mjs` 会用本机模拟直播页跑一遍并发上限 / 空闲让位 / 分片拦截 / 失败退避。

</details>

<details>
<summary><b>央视景观需要登录吗？为什么日志显示浏览器会话已启动？</b></summary>

<br>

不需要登录。日志中的「央视直播中国浏览器会话已启动」表示服务端启动无界面的 Chromium，执行央视官网播放器并获取临时 HLS 地址，不会打开登录页，也不会保存央视账号或 Cookie。若相邻日志出现「数字频道号 + 由于版权原因，请登录后观看」，该数字频道号属于咪咕，与央视景观无关。

央视 CDN 会同时校验播放清单和视频分片的官网请求头，普通播放器无法自行补齐，因此央视景观固定使用全代理：只有实际观看时才产生流量，单路常见约 1–3 Mbps，多个观看设备会叠加。升级后请重启服务或重新生成播放列表，并在播放器中刷新订阅；若解析失败，服务日志会明确显示「央视直播中国链接请求失败」及具体原因。

</details>

<details>
<summary><b>内置抓取模块和精选频道是否代表内容已经获得转载授权？</b></summary>

<br>

不代表。抓取模块说明的是软件能够与公开页面或接口协作，精选频道的检查目标是确认地址格式和播放可用性；两者都不是对节目版权、地域许可或转播授权的法律审查。公开可访问的地址也可能因权利限制、平台政策或地区差异随时失效。

请只在个人学习、研究以及你已获得授权的场景中使用，不要将服务公开售卖、重新广播、绕过付费或地域限制，也不要分享他人的账号凭据。对某项来源权利状态有疑问时，可在「🌐 源管理」关闭对应模块或精选频道，并优先使用自己的合法订阅或自有信号。权利人下架流程见[版权与侵权处理](#-版权与侵权处理)。

</details>

播放器订阅类型的快速选择请看上方[播放器适配](#-播放器适配)；遇到新的兼容性问题，欢迎提交 issue 补充。

### 📺 多套配置档（给不同电视各一套）

后台「📺 我的频道」标题行右侧可新建 / 切换配置档，每档独立维护隐藏 / 分组 / 排序 / 重命名，互不影响；每台电视填各自的地址（每档底部可复制），如 `http://你的IP:1905/interface.m3u?profile=woshi`。各档共享同一份底层频道与 EPG，新增电视不增加抓取成本；默认档地址不变、老用户零感知。

### 🧹 空白部署 / 纯频道管理

只想用自己的源时，用内容开关关掉自带内容（也避免同名分组撞车）：

| 需求 | 配置 |
| --- | --- |
| 彻底空白，自己加源 | `mblank=true` |
| 空白但保留抓取核心 | `mblank=true` + `menableMigu=true` |
| 只去掉自带的额外源 / 订阅 | `menableBuiltInSources=false` + `menableBuiltInSubscriptions=false` |

也可在后台「🌐 源管理」直接开关各卡片，保存即时生效。关闭 `menableMigu` 后体育赛事、回看与对应 EPG 不可用，属预期表现。

### 📡 公网地址 (mhost)

反向代理 / 域名访问 / 对外分享时填写（如 `http://yourdomain.com:1905`），仅内网使用留空即可。系统自动按访问来源选择播放列表里的地址：内网访问用内网地址，反代访问（带 `X-Forwarded-For`）用配置的公网地址；填 `http(s)://` 完整地址时不会强制补端口。

### 🔐 访问密码 (mpass)

设置后所有服务都要在 URL 带密码路径：`http://ip:port/密码/interface.m3u`、`http://ip:port/密码/admin` 等，播放列表内的频道链接自动注入密码路径，未授权访问返回 403。

### 🔧 本地运行（不用 Docker）

需要 Node.js 20+（推荐 22 LTS）；部分平台的频道需要中国大陆网络环境。

```bash
git clone https://github.com/akiralereal/iptv.git && cd iptv
node app.js
```

环境变量与 Docker 同名同义，例如：`mport=1905 mhost="http://localhost:1905" node app.js`（Windows PowerShell：`$Env:mport=1905; node app.js`）。

- **更新流程加单飞锁**：定时刷新、启动初始化与后台保存外部源可能并发调用 `update()`，并发改写同一批临时文件会损坏 `interface.txt` / `playback.xml`；现串行化执行
- **修复 Chromium 僵尸进程**：网页抓取（`fetch` 模式）启动的 Chromium 在容器内不再堆积 `<defunct>` 僵尸进程——镜像引入 `tini` 作为 init 进程回收孤儿子进程（`docker-compose.yml` 增加 `init: true`），`browser.close()` 增加超时与强杀进程组兜底（需**重建镜像/容器**后生效）
- **修复订阅分组乱码**：订阅内容改为按原始字节解码，自动识别 GBK/GB2312（中文 IPTV 列表常见）、UTF-8 及 BOM，分组名与频道名不再乱码
- **修复 HDR / H265 无法关闭**：环境变量 `menableHDR=false` / `menableH265=false` 之前因布尔与字符串比较问题始终无效，现可正常关闭
- **系统配置热更新**：在管理后台保存系统配置后大部分项即时生效，无需重启（监听端口与节目更新间隔仍需重启）
- **可关闭 token 刷新**：每月一次的咪咕 token 刷新（可能导致封号）现可通过 `refreshToken` 配置 / `mrefreshToken` 环境变量关闭
- **订阅导入报错优化**：所有镜像均失败时聚合显示每条线路的真实失败原因（不再是空白 `reason`）并给出排查提示；新增 `cdn.jsdelivr.net` 备用镜像
- **健壮性与清理**：配置文件改为**原子写入**（临时文件 + rename），避免并发/写入中断损坏 JSON；修复 `fileUtil` 同步函数误传回调的问题；分组内频道按「名称 + 地址」去重；修复 `androidURL.js` 中 `delay` 未引入导致 302 重试逻辑失效的隐藏问题；移除 `ddCalcuURL` 中无用的 WASM 死代码
